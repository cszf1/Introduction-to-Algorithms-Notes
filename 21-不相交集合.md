## 本章导读

### 🎯 什么是并查集？

**生活类比**：想象你在玩一个社交软件，需要处理以下操作：

1. **创建账号** → 相当于 `MAKE-SET`，每个人刚注册时都是独立的个体
2. **添加好友** → 相当于 `UNION`，把两个人所在的社交圈合并
3. **查看两人是否在同一社交圈** → 相当于 `FIND-SET`

并查集就是这样一种数据结构，专门处理"元素分组"问题的高速工具。

### 📊 为什么需要并查集？

在很多算法问题中，我们需要：
- 判断两个元素是否属于同一个集合
- 将两个集合合并成一个大集合
- 高效处理成千上万次的合并和查询

**传统方法的问题**：
- 列表存储：合并 O(n)，查询 O(n)
- 数组索引：查询 O(1)，但合并需要遍历整个数组 O(n)

**并查集的优势**：经过优化的并查集，每次操作接近 O(1)！

## 21.1 不相交集合的操作

### 21.1.1 三个核心操作

```
┌─────────────────────────────────────────────────────────────────┐
│                     不相交集合的三个基本操作                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. MAKE-SET(x)    创建新集合                                    │
│     └─ 创建一个只包含元素 x 的新集合                              │
│     └─ x 成为这个集合的"代表元素"                                 │
│                                                                 │
│  2. UNION(x, y)    合并集合                                      │
│     └─ 将包含 x 和 y 的两个集合合并                              │
│     └─ 合并后产生一个新的集合代表                                 │
│                                                                 │
│  3. FIND-SET(x)    查找集合代表                                  │
│     └─ 返回指向包含 x 的集合的指针                               │
│     └─ 用于判断两个元素是否在同一个集合                          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 21.1.2 形式化定义

设 **S** 是一个不相交集合的集合：
```
S = {S₁, S₂, ..., Sₖ}
```

每个集合 `Sᵢ` 用其中的某个**代表元素（Representative）**来标识。

### 21.1.3 伪代码实现

```伪代码
MAKE-SET(x)
    x.p = x              // 自身指向自身（根节点）
    x.rank = 0            // 初始秩为0

UNION(x, y)
    LINK(FIND-SET(x), FIND-SET(y))

LINK(x, y)
    if x.rank > y.rank
        y.p = x           // 小秩指向大秩
    else
        x.p = y
        if x.rank == y.rank
            y.rank = y.rank + 1

FIND-SET(x)
    if x ≠ x.p
        x.p = FIND-SET(x.p)  // 路径压缩
    return x.p
```

### 21.2.2 链表表示的问题

**简单链表表示的缺陷**：

```
┌─────────────────────────────────────────────────────────────────┐
│                     加权合并启发式策略                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  问题：如果总是把一个集合接到另一个集合后面                        │
│                                                                 │
│  UNION(S₁, S₂) → UNION(S₁∪S₂, S₃) → UNION(S₁∪S₂∪S₃, S₄) → ...   │
│                                                                 │
│  结果：可能形成很长的链表，查找效率低下！                         │
│                                                                 │
│  解决方案：加权合并，总是把短的链表接到长的链表上                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 21.2.3 加权合并策略

```
┌─────────────────────────────────────────────────────────────────┐
│                     加权合并示例                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  合并前：                                                        │
│  ┌─────────────────┐      ┌───────────┐                        │
│  │ S₁ (长度=4)     │      │ S₂ (长度=2)│                        │
│  │ a → b → c → d  │      │ e → f     │                        │
│  └─────────────────┘      └───────────┘                        │
│                                                                 │
│  ❌ 错误做法：把 S₁ 接到 S₂ 后面（长+短 = 5）                     │
│  ✓ 正确做法：把 S₂ 接到 S₁ 后面（长+短 = 5）                     │
│                                                                 │
│  合并后：                                                        │
│  ┌─────────────────────────────────────────┐                    │
│  │ S₁∪S₂: a → b → c → d → e → f          │                    │
│  └─────────────────────────────────────────┘                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**链表表示的复杂度**：

| 操作 | 基本实现 | 加权合并 |
|:---:|:---:|:---:|
| MAKE-SET | O(1) | O(1) |
| FIND-SET | O(1) | O(1) |
| UNION | O(1) | O(1) |
| FIND-SET(查找代表) | O(n) | O(min(n₁, n₂)) |

```
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   森林表示：                                                     │
│   ┌──────────────────────┐     ┌──────────────────────┐        │
│   │       树 1            │     │       树 2            │        │
│   │                       │     │                       │        │
│   │        c              │     │        f              │        │
│   │       / \             │     │       / \             │        │
│   │      b   e            │     │      d   g            │        │
│   │     /                 │     │                       │        │
│   │    a                  │     │                       │        │

│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 21.3.2 两种关键优化策略

#### 🎯 策略一：按秩合并（Union by Rank）

**生活类比**：想象两个帮派合并，大的帮派当老大，小的帮派当小弟。

**核心思想**：总是把**秩（rank）较小**的树合并到**秩较大**的树上。

```
┌─────────────────────────────────────────────────────────────────┐
│                     按秩合并图解                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  合并前：                                                        │
│                                                                 │
│       秩=2                    秩=1                              │
│       ┌───┐                   ┌───┐                            │
│       │ A │                   │ B │                            │
│      /│   │\                 /│   │\                          │
│     / └───┘ \               /   └───┘ \                          │
│    ▼         ▼             ▼           ▼                       │
│   ┌───┐     ┌───┐         ┌───┐       ┌───┐                     │
│   │   │     │   │         │   │       │   │                    │
│   └───┘     └───┘         └───┘       └───┘                     │
│   / \                                                             │
│  ▼   ▼                                                           │
│                                                                 │
│  执行 UNION(A, B)：                                              │
│  由于 rank(A)=2 > rank(B)=1，所以让 B 的根指向 A                 │
│                                                                 │
│  合并后：                                                        │
│                    ┌───┐                                        │
│                    │ A │  ← 秩不变，仍为2                        │
│                   /│   │\                                       │
│                  / └───┘ \                                      │
│                 ▼         ▼                                     │
│               ┌───┐     ┌───┐                                   │
│               │   │     │   │                                   │
│               └───┘     └───┘                                   │
│               / \                                               │
│              ▼   ▼                                              │
│             ┌───┐ ┌───┐                                         │
│             │ B │ │   │  ← B 成为 A 的子树                       │
│             └───┘ └───┘                                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 🎯 策略二：路径压缩（Path Compression）

**生活类比**：你去公司找老板问"这件案子谁负责？"，老板说"找张经理"，然后张经理说"找李主管"...路径压缩就是：**直接告诉你老板的电话，以后有事直接打给老板**。

**核心思想**：在 FIND 操作时，将路径上的所有节点直接指向根节点。

```
┌─────────────────────────────────────────────────────────────────┐
│                     路径压缩图解                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  FIND-SET(a) 执行前：                                            │
│                                                                 │
│         根                                                       │
│         ┌───┐                                                   │
│         │ r │                                                   │
│         └─┬─┘                                                   │
│           │                                                     │
│         ┌─┴─┐                                                   │
│         │ x │                                                   │
│         └─┬─┘                                                   │
│           │                                                     │
│         ┌─┴─┐                                                   │
│         │ y │                                                   │
│         └─┬─┘                                                   │
│           │                                                     │
│         ┌─┴─┐                                                   │
│         │ a │  ← 查找 a 的根                                    │
│         └───┘                                                   │
│                                                                 │
│  执行过程（两趟方法）：                                          │
│  第一趟（向上）：a → y → x → r（找到根）                         │
│  第二趟（向下）：更新每个节点的父指针指向根                        │
│                                                                 │
│  FIND-SET(a) 执行后：                                            │
│                                                                 │
│         ┌───┐                                                   │
│         │ r │                                                   │
│  ┌──────┴───┴──────┐                                            │
│  │                  │                                            │
│  ▼                  ▼                                            │
│ ┌───┐   ┌───┐     ┌───┐                                         │
│ │ x │   │ y │     │ a │  ← 所有节点直接指向根                    │
│ └───┘   └───┘     └───┘                                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 21.3.3 两种策略的叠加效果

```
┌─────────────────────────────────────────────────────────────────┐
│              按秩合并 + 路径压缩 = 近乎 O(1)                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  没有优化：树可能退化成链表，FIND 操作 O(n)                       │
│                                                                 │
│  只有按秩合并：树深度 ≤ log n，FIND 操作 O(log n)                │
│                                                                 │
│  按秩合并 + 路径压缩：                                           │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │                                                         │    │
│  │   m 次操作的总时间：O(m α(n))                           │    │
│  │                                                         │    │
│  │   其中 α(n) 是 Ackermann 函数的反函数，增长极其缓慢       │    │
│  │   对于实际应用：α(n) ≤ 4                                │    │
│  │                                                         │    │
│  └─────────────────────────────────────────────────────────┘    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 21.3.4 Ackermann 函数与 α(n)

```
┌─────────────────────────────────────────────────────────────────┐
│                     Ackermann 函数                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  A(k, n) 的定义：                                               │
│                                                                 │
│  A(1, n) = 2n           （线性增长）                             │
│  A(2, n) = 2^n          （指数增长）                             │
│  A(3, n) = 2↑↑n        （双重指数/迭代指数）                     │
│  A(4, n) = 2↑↑↑n       （更高层次）                             │
│  ...                                                            │
│                                                                 │
│  α(n) = min{k ≥ 1 | A(k, 1) ≥ n}                               │
│                                                                 │
│  α(n) 的增长速度：                                              │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  n           │  α(n)        │  说明                     │    │
│  ├─────────────────────────────────────────────────────────┤    │
│  │  1           │  1           │                           │    │
│  │  2           │  2           │                           │    │
│  │  3           │  3           │                           │    │
│  │  4           │  4           │                           │    │
│  │  5           │  4           │  A(4,1)=65536 > 5          │    │
│  │  ...         │  4           │  极大的 n 才开始变化        │    │
│  │  65536       │  4           │                           │    │
│  │  65537       │  5           │                           │    │
│  │  2^65536     │  5           │  一个宇宙都装不下的数       │    │
│  └─────────────────────────────────────────────────────────┘    │
│                                                                 │
│  结论：对于任何实际问题，α(n) ≤ 5，可以认为是常数！               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 21.4 应用场景

### 21.4.1 Kruskal 最小生成树算法

**算法思想**：Kruskal 算法使用并查集来判断是否要加入某条边。

```
┌─────────────────────────────────────────────────────────────────┐
│                     Kruskal 算法流程                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 初始状态：每个顶点都是独立的集合                              │
│                                                                 │
│  2. 将所有边按权值从小到大排序                                   │
│                                                                 │
│  3. 依次处理每条边：                                             │
│     ┌─────────────────────────────────────────────┐            │
│     │  if FIND-SET(u) ≠ FIND-SET(v):              │            │
│     │      // u 和 v 不在同一集合，不形成环        │            │
│     │      加入边 (u, v)                           │            │
│     │      UNION(u, v)                             │            │
│     └─────────────────────────────────────────────┘            │
│                                                                 │
│  4. 重复直到选择了 n-1 条边                                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**完整示例**：

```

├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  原图：                            最小生成树：                   │
│                                                                 │
│       A──7──B                        A──7──B                     │
│      /│\     \                      /│      \                   │
│    5 /  │  9 \                    5 /  │      \                  │
│    /  8│     \                    /  8│       \                 │

│    \   |   /                        \   |     /                 │

│                                                                 │
│  边排序：CD(1), DF(2), DE(4), AC(5), AB(7), BD(8), AD(9)       │
│                                                                 │
│  执行过程：                                                      │
│  1. 选 CD(1): C 和 D 不连通 → 加入，合并{C,D}                   │

│                                                                 │
```

### 21.4.2 等价关系与连通分量

**数学背景**：

```
┌─────────────────────────────────────────────────────────────────┐
│                     等价关系的三个性质                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  关系 R 是等价关系，当且仅当它是：                               │
│                                                                 │
│  1. 自反的（Reflexive）：aRa 对所有 a 成立                      │
│                                                                 │
│  2. 对称的（Symmetric）：若 aRb，则 bRa                         │
│                                                                 │
│  3. 传递的（Transitive）：若 aRb 且 bRc，则 aRc                  │
│                                                                 │
│  等价类（Equivalence Class）：                                  │
│  由等价关系划分的集合，每个元素属于恰好一个等价类                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**生活类比**：手机网络中的"好友圈"
- 自反：你自己和你自己是一个圈子的
- 对称：如果你在小明的圈子里，小明也在你的圈子里
- 传递：如果你在小明的圈子里，小明在小红的圈子里，那你也在小红的圈子里

### ⚠️ 易错点

1. **FIND-SET 要递归调用**：不要忘记递归返回后将当前节点指向根
2. **UNION 要先 FIND**：合并前必须先找到两个元素的根
3. **按秩合并的秩更新**：只有当两个根的秩相等时，才增加秩
4. **路径压缩不影响秩**：压缩路径不会改变任何节点的秩

## FAQ 疑难解答

### Q1: 为什么叫"不相交"集合？

**A**: 因为并查集维护的多个集合之间**互不相交**，即一个元素只能属于一个集合，不能同时属于两个集合。这就像一个班级的学生分组，每个学生只能属于一个小组。

### Q2: 什么是"代表元素"？

**A**: 代表元素是用来标识一个集合的成员。在森林表示中，根节点就是代表元素。任何两个元素属于同一集合，当且仅当它们的根相同。

### Q3: 为什么路径压缩叫"压缩"？

**A**: 因为它"压缩"了查找路径！原本从节点到根可能经过多个中间节点，路径压缩后，所有节点直接指向根，"缩短"了路径长度。

### Q4: α(n) 到底有多大？

**A**: 对于任何你能想到的 n 值（小于宇宙中原子数），α(n) ≤ 5。可以说 α(n) ≈ 4 是一个极其保守的上界。所以 O(α(n)) 可以认为是 O(1)。

### Q5: 什么时候用链表表示，什么时候用森林表示？

**A**: 
- 链表表示：实现简单，适合教学
- 森林表示：工业级应用，效率更高

实际几乎总是使用森林表示。

### Q6: 并查集和哈希表有什么区别？

**A**: 
- 哈希表：用于快速查找键值对
- 并查集：用于管理集合的合并和判断元素是否在同一集合

两者解决的问题不同，不能互换。

```python
#!/usr/bin/env python3
"""
并查集（不相交集合）实现
Disjoint Set (Union-Find) Implementation

包含两种优化策略：
1. 按秩合并 (Union by Rank)
2. 路径压缩 (Path Compression)
"""

class UnionFind:
    """
    并查集数据结构
    
    核心思想：
    - 每个元素用一个节点表示
    - 每个集合用一棵树表示
    - 树的根节点是集合的代表元素
    
    优化策略：
    - 按秩合并：秩小的树合并到秩大的树
    - 路径压缩：FIND时让路径上的所有节点直接指向根
    """
    
    def __init__(self, n: int):
        """
        初始化并查集
        
        Args:
            n: 元素个数（0 到 n-1）
        
        时间复杂度: O(n)
        """
        # 父节点数组，parent[i] 表示元素 i 的父节点
        self.parent = list(range(n))
        
        # 秩数组，rank[i] 表示以 i 为根的树的深度上界
        self.rank = [0] * n
        
        # 连通分量计数
        self.count = n
    
    def find(self, x: int) -> int:
        """
        查找元素 x 所属集合的代表（根节点）
        
        采用路径压缩优化：
        - 递归找到根节点
        - 回溯时让路径上的所有节点直接指向根
        
        Args:
            x: 要查找的元素
            
        Returns:
            元素 x 所属集合的根节点
        
        时间复杂度: O(α(n)) ≈ O(1)
        """
        # 路径压缩：如果 x 不是根，则递归查找根
        # 并将 x 直接指向根
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]
    
    def find_iterative(self, x: int) -> int:
        """
        迭代版本的 FIND（不使用递归）
        
        Args:
            x: 要查找的元素
            
        Returns:
            元素 x 所属集合的根节点
        """
        # 第一趟：找到根
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        
        # 第二趟：路径压缩
        while self.parent[x] != root:
            next_x = self.parent[x]
            self.parent[x] = root
            x = next_x
        
        return root
    
    def union(self, x: int, y: int) -> None:
        """
        合并元素 x 和 y 所属的集合
        
        采用按秩合并策略：
        - 找到两个元素的根
        - 如果已经在同一集合，无需合并
        - 否则，将秩较小的根合并到秩较大的根
        
        Args:
            x: 第一个元素
            y: 第二个元素
            
        时间复杂度: O(α(n)) ≈ O(1)
        """
        # 找到两个元素的根
        root_x = self.find(x)
        root_y = self.find(y)
        
        # 如果已经在同一个集合，无需合并
        if root_x == root_y:
            return
        
        # 按秩合并：将秩较小的树合并到秩较大的树
        if self.rank[root_x] < self.rank[root_y]:
            # root_x 的秩较小，让 root_x 指向 root_y
            self.parent[root_x] = root_y
        elif self.rank[root_x] > self.rank[root_y]:
            # root_y 的秩较小，让 root_y 指向 root_x
            self.parent[root_y] = root_x
        else:
            # 秩相等，任选一个作为父，并增加其秩
            self.parent[root_y] = root_x
            self.rank[root_x] += 1
        
        # 更新连通分量计数
        self.count -= 1
    
    def connected(self, x: int, y: int) -> bool:
        """
        判断两个元素是否在同一个集合中
        
        Args:
            x: 第一个元素
            y: 第二个元素
            
        Returns:
            如果 x 和 y 在同一集合返回 True，否则返回 False
            
        时间复杂度: O(α(n)) ≈ O(1)
        """
        return self.find(x) == self.find(y)
    
    def get_count(self) -> int:
        """
        获取当前连通分量的数量
        
        Returns:
            连通分量的数量
        """
        return self.count
    
    def get_size(self, x: int) -> int:
        """
        获取元素 x 所在集合的大小（包含该元素的节点数）
        
        注意：这是朴素实现，实际中通常不跟踪集合大小
        因为跟踪大小会影响路径压缩的效果
        
        Args:
            x: 任意元素
            
        Returns:
            x 所在集合的大小
        """
        # 找到根
        root = self.find(x)
        
        # 统计根的子树大小
        size = 1
        for i in range(len(self.parent)):
            if self.find(i) == root:
                size += 1
        
        return size
    
    def get_all_components(self) -> dict:
        """
        获取所有连通分量的信息
        
        Returns:
            一个字典，键为根节点，值为该连通分量中的所有节点
        """
        components = {}
        for i in range(len(self.parent)):
            root = self.find(i)
            if root not in components:
                components[root] = []
            components[root].append(i)
        return components
    
    def display(self) -> None:
        """
        显示并查集的当前状态
        """
        print(f"Parent数组: {self.parent}")
        print(f"Rank数组:   {self.rank}")
        print(f"连通分量数: {self.count}")
        print("各连通分量:")
        for root, members in self.get_all_components().items():
            print(f"  集合 {root}: {members}")
```

### C++ 实现

```cpp
/*
 * 并查集（不相交集合）C++ 实现
 * Disjoint Set (Union-Find) Implementation in C++
 * 
 * 包含两种优化策略：
 * 1. 按秩合并 (Union by Rank)
 * 2. 路径压缩 (Path Compression)
 */

#include <iostream>
#include <vector>
#include <algorithm>
#include <map>
using namespace std;

/**
 * UnionFind 类
 * 
 * 数据结构：
 * - parent[i]: 元素 i 的父节点，根节点的父节点是自身
 * - rank[i]: 元素 i 所在树的秩（深度上界）
 */
class UnionFind {
private:
    vector<int> parent;  // 父节点数组
    vector<int> rank;    // 秩数组
    int count;           // 连通分量数量

public:
    /**
     * 构造函数
     * @param n 元素个数（0 到 n-1）
     * 
     * 时间复杂度: O(n)
     */
    UnionFind(int n) : parent(n), rank(n, 0), count(n) {
        // 初始化：每个元素都是自己的父节点（自己是根）
        for (int i = 0; i < n; i++) {
            parent[i] = i;
        }
    }
    
    /**
     * FIND 操作：查找元素 x 所属集合的根
     * 
     * 采用路径压缩优化：
     * - 递归找到根节点
     * - 回溯时让路径上的所有节点直接指向根
     * 
     * @param x 要查找的元素
     * @return 元素 x 所属集合的根节点
     * 
     * 时间复杂度: O(α(n)) ≈ O(1)
     */
    int find(int x) {
        // 路径压缩：如果 x 不是根，则递归查找根
        // 并将 x 直接指向根
        if (parent[x] != x) {
            parent[x] = find(parent[x]);
        }
        return parent[x];
    }
    
    /**
     * UNION 操作：合并元素 x 和 y 所属的集合
     * 
     * 采用按秩合并策略：
     * - 找到两个元素的根
     * - 如果已经在同一集合，无需合并
     * - 否则，将秩较小的根合并到秩较大的根
     * 
     * @param x 第一个元素
     * @param y 第二个元素
     * 
     * 时间复杂度: O(α(n)) ≈ O(1)
     */
    void unite(int x, int y) {
        // 找到两个元素的根
        int rootX = find(x);
        int rootY = find(y);
        
        // 如果已经在同一个集合，无需合并
        if (rootX == rootY) {
            return;
        }
        
        // 按秩合并：将秩较小的树合并到秩较大的树
        if (rank[rootX] < rank[rootY]) {
            // rootX 的秩较小，让 rootX 指向 rootY
            parent[rootX] = rootY;
        } else if (rank[rootX] > rank[rootY]) {
            // rootY 的秩较小，让 rootY 指向 rootX
            parent[rootY] = rootX;
        } else {
            // 秩相等，任选一个作为父，并增加其秩
            parent[rootY] = rootX;
            rank[rootX]++;
        }
        
        // 更新连通分量计数
        count--;
    }
    
    /**
     * 判断两个元素是否在同一个集合中
     * @param x 第一个元素
     * @param y 第二个元素
     * @return 如果在同一集合返回 true
     */
    bool connected(int x, int y) {
        return find(x) == find(y);
    }
    
    /**
     * 获取当前连通分量的数量
     * @return 连通分量的数量
     */
    int getCount() const {
        return count;
    }
    
    /**
     * 获取所有连通分量
     * @return 映射表，键为根节点，值为该连通分量中的所有节点
     */
    map<int, vector<int>> getComponents() {
        map<int, vector<int>> components;
        for (int i = 0; i < parent.size(); i++) {
            int root = find(i);
            components[root].push_back(i);
        }
        return components;
    }
    
    /**
     * 显示并查集的当前状态
     */
    void display() {
        cout << "Parent数组: ";
        for (int p : parent) {
            cout << p << " ";
        }
        cout << endl;
        
        cout << "Rank数组:   ";
        for (int r : rank) {
            cout << r << " ";
        }
        cout << endl;
        
        cout << "连通分量数: " << count << endl;
        
        cout << "各连通分量:" << endl;
        map<int, vector<int>> components = getComponents();
        for (auto& pair : components) {
            cout << "  集合 " << pair.first << ": ";
            for (int v : pair.second) {
                cout << v << " ";
            }
            cout << endl;
        }
    }
};

struct Edge {

    int weight;    // 边的权值
    
    // 按权值升序排序

void kruskalMST(int n, const vector<Edge>& edges) {
    cout << "\n========================================" << endl;
    cout << "Kruskal 最小生成树算法示例" << endl;
    cout << "========================================" << endl;
    
    // 按权值排序
    vector<Edge> sortedEdges = edges;
    sort(sortedEdges.begin(), sortedEdges.end());
    
    cout << "\n按权值排序后的边：" << endl;
    for (const Edge& e : sortedEdges) {
        cout << "  (" << e.u << ", " << e.v << ", weight=" << e.weight << ")" << endl;
    }
    
    // Kruskal 算法
    UnionFind uf(n);
    vector<Edge> mstEdges;
    int totalWeight = 0;
    
    cout << "\n执行 Kruskal 算法：" << endl;
    for (const Edge& e : sortedEdges) {
        if (uf.find(e.u) != uf.find(e.v)) {
            // 这条边不会形成环，加入 MST
            mstEdges.push_back(e);
            totalWeight += e.weight;
            cout << "  加入边 (" << e.u << ", " << e.v << ")，"
                 << "权值=" << e.weight
                 << "，当前总权值=" << totalWeight << endl;
            
            // 合并两个集合
            uf.unite(e.u, e.v);
            
            // MST 有 n-1 条边时完成
            if (mstEdges.size() == n - 1) {
                break;
            }
        }
    }
    
    cout << "\n【最小生成树结果】" << endl;
    cout << "  边数: " << mstEdges.size() << endl;
    cout << "  总权值: " << totalWeight << endl;
    cout << "  边列表:" << endl;
    for (const Edge& e : mstEdges) {
        cout << "    (" << e.u << ", " << e.v << ", weight=" << e.weight << ")" << endl;
    }
}
```
